KEY FINDINGS
=============

ROOT CAUSE
----------
Monolithic main() function (lines 35-249) responsible for:
  • Logging setup
  • Database initialization
  • S3/Mail/Stripe/Typesense/LLM setup
  • 138 route registrations
  • CORS configuration
  • Server startup

Plus 2 package-level globals (var s, var h) that are only initialized in main()

IMPACT
------
Router inaccessible to tests - cannot create router without starting server
Middleware ordering implicit - determined by function nesting, not explicit
Configuration scattered - 40+ os.Getenv() calls throughout codebase
CORS untestable - different behavior in production vs. tests
Async operations uncoordinated - Typesense, embeddings fire as goroutines
Dependencies unmockable - cannot inject test doubles independently

OBSTACLES RANKED BY IMPACT
---------------------------
1. Router composition untestable (CRITICAL)
   Cannot verify all 138 routes, methods, or middleware composition

2. CORS not tested (HIGH)
   Production behavior not covered by tests

3. Middleware ordering implicit (HIGH)
   Order determined by nesting, subtle bugs possible

4. Dependencies hard to mock (MEDIUM)
   All-or-nothing dependency injection through Server struct

5. Configuration scattered (MEDIUM)
   No single source of truth for environment variables

SOLUTION: 5-PHASE REFACTORING
==============================

Recommended approach: Extract and decentralize code in 5 independent phases

Phase 1: Extract Configuration (1-2 hours, LOW RISK)
  Files to create:
    • pkg/config/config.go - ServerConfig, DatabaseConfig, ServiceConfig
    • pkg/config/config_test.go - Configuration loading tests
  Outcome:
    • Single source of truth for all environment variables
    • Configuration validation and typing
    • Enables testing with different configs
  Impact:
    • main.go becomes smaller, cleaner
    • Bootstrap functions accept config parameters
    • Tests can inject different configurations

Phase 2: Extract Router Builder (2-3 hours, LOW RISK)
  Files to create:
    • pkg/routes/builder.go - BuildRouter() function
    • pkg/routes/builder_test.go - Router composition tests
  Outcome:
    • Router can be created without starting server
    • Routes organized by feature (auth, cards, tasks, etc.)
    • 138 routes accessible to tests
    • Can verify all routes exist with correct methods/middleware
  Impact:
    • main.go further reduced
    • Router composition testable
    • Adding routes becomes simple and documented

Phase 3: Middleware Composition Layer (2-3 hours, LOW RISK)
  Files to create:
    • pkg/middleware/chain.go - HandlerChain type
    • pkg/middleware/chain_test.go - Middleware ordering tests
  Outcome:
    • Middleware ordering explicit and testable
    • Reusable chains (protected, admin, public)
    • Tests can verify middleware order
    • Middleware composition self-documenting
  Impact:
    • No more implicit nesting confusion
    • Subtle ordering bugs prevented
    • Easier to add/modify middleware

Phase 4: CORS Wrapper Extraction (1 hour, VERY LOW RISK)
  Files to create:
    • pkg/middleware/cors.go - WithCORS() function
    • pkg/middleware/cors_test.go - CORS behavior tests
  Outcome:
    • CORS testable separately
    • Consistent behavior production/tests
    • CORS configuration explicit
  Impact:
    • CORS no longer tight-coupled to main()
    • Can test CORS + auth integration
    • No production/test behavior divergence

Phase 5: Test Suite Expansion (3-4 hours, VERY LOW RISK)
  Files to create:
    • integration/router_test.go - All routes exist
    • integration/middleware_test.go - Auth middleware integration
    • integration/full_flow_test.go - Request flow through all layers
    • integration/config_test.go - Configuration variations
  Outcome:
    • 30+ new integration tests
    • Router composition fully tested
    • Middleware integration verified
    • CORS behavior covered by tests
    • Configuration variations tested
  Impact:
    • Production behavior covered by tests
